# Missed Sessions — M1.3 Reconcile Endpoint

**Milestone:** P1 / M1.3
**Date:** 2026-10-07
**Status:** COMPLETE
**Prompt:** docs/features/missed-sessions/05-prompts.md, M1.3

## 1. Summary

`POST /api/goal/reconcile` now reports, for the signed-in user's active plan v2 goal, how every day is classified (done, missed, rest, planned) and whether a gap is open. It writes nothing and answers the same way however often it is called. Old goals and users without an active goal get `{ applies: false, reason }`. The app calls it once per load, before fetching the goal, and a failure there never affects loading. Nothing on screen uses the result yet (P3). With this, P1 is complete.

## 7. Carry-overs for P2

1. Carry-forward goes at the marked comment in `POST /reconcile`, after `buildReconcileResult` and before the response. Once it writes, idempotency (3.4) must hold across repeated and concurrent calls (two open tabs): a step must never be carried twice. The M1.1 report suggested a `carriedFrom` marker for this.
2. The response may need fields for what moved (carried, dropped) when P2 starts writing; extend `ReconcileResult` then, not before.
3. M2.2 lists "P1 step already done (no carry)" as a test case. Completion is per day only (ND-8), so that case cannot be detected from stored data; M2.2's prompt must resolve it.
4. Each app load now makes one extra request before the goal fetch. Reconcile is read-only and small; revisit if load time matters.
