# Missed Sessions — M3.1 Miss Notice

**Milestone:** P3 / M3.1
**Date:** 2026-10-07
**Status:** COMPLETE (frontend only; `MISSED_SESSIONS_CARRY_ENABLED` untouched, see the release checklist in section 8)
**Prompt:** docs/features/missed-sessions/05-prompts.md, M3.1 (commit `f7bfd9a`)

## 1. Summary

- **Today and the Dashboard now read reconcile.** `GoalContext` keeps the plan v2 reconcile body as `reconciliation`. One shared helper, `missNotice` in `lib/today.ts`, turns its `signals` into what both screens say, so they cannot disagree (ND-19).
- **Today** shows at most one line in the existing `Callout`, only for `carried` and `dropped`, only on today's own view, never on a rest day. The old callout ("Yesterday's step wasn't completed") is gone.
- **Dashboard.** The status line's `slipped` input is replaced by the same notice. `isYesterdayPending` drives nothing any more and was removed.
- **A tab left open overnight catches up.** When the page is seen again on a new local date, the same load runs again: reconcile, then the goal.
- **Unchanged:** no backend change, no schema change, no new copy beyond R4 and R5, the switch untouched. `gentle_return` and `swap_offer` render nothing until M3.2 and M3.3.
- **Before the switch is on,** `signals.carried` is always empty (only stored moves are reported), so only the `dropped` line can appear in production today. That line is true with the switch off too.

## 3. Every user-facing string

Added (`{Day}` is "Yesterday" when the day is yesterday in the user's timezone, otherwise its weekday; `{Weekday}` is the receiving day's weekday):

| Where | When | String |
|---|---|---|
| Today | `carried`, into today | `{Day}'s session didn't happen. We moved its most important step into today, so today stays the same length.` |
| Today | `carried`, to a later day | `{Day}'s session didn't happen. We moved its most important step to {Weekday}, so that day stays the same length.` |
| Today | `dropped` | `{Day}'s session didn't happen. Nothing needs making up: the plan carries on as it is.` |
| Dashboard | `carried`, into today | `{Day}'s most important step is part of today's session.` |
| Dashboard | `dropped` | `{Day} slipped past. No catching up needed, just today.` |

Removed:
- "Yesterday's step wasn't completed".
- "Here's how we can recover. Don't try to double up or rush. Focus entirely on today's step and keep your momentum forward."
- The Dashboard's fixed "Yesterday slipped past. No catching up needed, just today." The same sentence now comes from the `dropped` signal with `{Day}`.

None of these contains "missed", "behind", "failed", "why" or a status label. The drop reason is never shown.

## 7. Discrepancies and decisions

1. **Copy source.** Feature Definition section 12 gives a direction ("…moved the most important step to [day], so today stays the same length"). The prompt's R4 strings are the exact, final ones and are used verbatim.
2. **Between local midnight and the receiving day's close,** a carry can still be reported while its receiving day is already yesterday. The `carried` signal lasts until the receiving day closes: bedtime + 2 h, at most 04:00.
   - Today then shows the "later day" line naming that day, for example "Monday's session didn't happen. We moved its most important step to Tuesday, so that day stays the same length." It is true; Tuesday is later than Monday.
   - The Dashboard keeps its normal line, because the step is not part of today.
3. **A body for another goal is ignored.** `missNotice` returns nothing when `reconciliation.goalId` is not the active goal's id, for example right after a reset, before the next load.
4. **"Carried into today" also shows once today is done.** The line stays true. On the Dashboard the finished-day line has priority, as before.
5. **The new-day check** compares the local date of the last load's start with the current local date, both read in the user's stored timezone at the moment of the event. A timezone that loads after the first reconcile cannot cause a spurious rerun.
6. **Far-back weekdays.** `{Day}` is a weekday name for anything but yesterday. A `dropped` date a week or more back would be ambiguous. The backend only reports the most recent closed practice day, and a run of 3+ misses becomes `gentle_return`, so this is not expected; noted, not handled.
7. **`findYesterdayTask`** is kept with its test. It no longer has a production caller, and the prompt removes only `isYesterdayPending`.
8. **The old callout had an `h3`.** The new notice is one sentence in a `<p>`, so the step card has one heading fewer. Nothing linked to it.

No STOP condition applied: the backend shape matches `MissedSignals`; every R4/R5 string is true for the case it is shown in; no backend change was needed; the Dashboard and Today read the same `reconciliation` through one helper.

## 8. Release checklist: turning carry-forward on (ND-15, 04-phases.md 2.4)

Do this only after this branch is merged to `main` and the Vercel deploy that carries it is live.

**Turn on**
1. Confirm the M3.1 frontend is live. Open production with a plan v2 goal; the old "Yesterday's step wasn't completed" callout must no longer appear on a day after a pending one.
2. Render dashboard → service `achivii-api` → Environment. Set `MISSED_SESSIONS_CARRY_ENABLED` to exactly `true` (lowercase; anything else is off) and save, choosing the option that redeploys or restarts with the new value. It is `sync: false` in `render.yaml`, so a Blueprint sync never overwrites it.
3. Wait for the deploy to finish and `/api/health` to answer.

**Confirm in production**

Use a plan v2 test account with a pending practice day whose next practice day is open. Wait until the pending day closes (the user's bedtime + 2 h, capped at 04:00 local time).

4. Open the app. In the network panel, the `POST /api/goal/reconcile` response has:
   - `carry.enabled: true`;
   - one entry in `carry.written` for that day, with its `toDate`;
   - `signals.notice: "carried"`.
5. The receiving day's `detailedSteps` (in `GET /api/goal/active`) holds the moved step, with a `carriedFrom` marker naming the source task and date. Its total minutes are not higher than before.
6. Today shows exactly one line, matching the dates:
   - "Yesterday's session didn't happen. We moved its most important step into today, so today stays the same length." when the step moved into today;
   - the "to {Weekday}" line when it moved to a later day.
7. The Dashboard agrees: "Yesterday's most important step is part of today's session." when the step moved into today.
8. Reload twice. The step moved once:
   - `carry.written` is now empty and the move appears in `carry.alreadyCarried`;
   - the receiving day has one carried step, not two;
   - the line is still there.

**Turn off (kill switch)**

9. Render → `achivii-api` → Environment. Set `MISSED_SESSIONS_CARRY_ENABLED` to `false` or delete it, then save and redeploy as above. No code deploy is needed. From then on:
   - reconcile writes nothing (`carry.enabled: false`);
   - mark missed, swap and carry-now answer 409 `carry_disabled`.
10. Turning it off does not undo carries already stored.
   - They keep their `carriedFrom` markers, which also store the steps they replaced (ND-13), so each one can be reversed.
   - There is no tool or endpoint for that yet; a reversal would be a manual database edit.
   - Their notice keeps showing until each receiving day closes.
