## 1. Summary

- **Three actions, behind the switch.** With `reconciliation.carry.enabled` true, Today's view of today offers:
  - **the swap offer:** one line in the existing `Callout`, with "Swap the days" and "Just move its main step";
  - **"Set today aside":** a quiet button that opens a dialog;
  - **"Swap with another day":** a quiet button that opens a dialog listing the days it can swap with.
- **One round trip each.** Every action answers with the reconcile body. `GoalContext.applyReconciliation` keeps it as `reconciliation`, then reloads the goal. The result shows through the normal notice line.
- **The Dashboard agrees** through the same `missNotice`: the swap-offer line (no buttons), and "Today's session is set aside. No catching up needed." after setting today aside.
- **Switch off: nothing changes.** `missNotice` gives no swap offer and no set-aside line, `todayActions` gives null, and M3.1's lines read exactly as before.
- **One STOP, resolved by the product owner** (section 7, item 1): the dialog body is "Nothing gets longer." only.
- **Today.tsx stays self-contained:** 15 changed lines (the notice strings, one hook call, two components). The UI is in `components/today/PlanActions.tsx` and `usePlanAction.ts`.

## 7. STOP, discrepancies and decisions

1. **STOP (resolved): the dialog body as written was untrue for some days.** R5's body was "Its most important step moves to the next practice day if it fits there. Nothing gets longer." The first sentence is false when:
   - today is a **key session**: it is held for a swap offer, not moved (ND-14);
   - the step is **high-load** (for example every run10k and recomp running step): it is dropped (AC-13);
   - today is the **last practice day** of the week or the test day comes next: there is no receiving day;
   - the step **does not fit**, or the next day is done or in a gap: it is dropped.

   The product owner chose the body **"Nothing gets longer."** only, which is true in every case. The result line after the call says what actually happened.
2. **Where the swap offer shows.** R4 says "on Today's view of the offer's receiving day"; R5 shows the offer for today right after setting today aside, when its receiving day is later.
   - Both are met by showing the offer on Today's view of today.
   - In practice the receiving day of a past miss is today: the backend offers only while the receiving day is open.
   - An offer whose receiving day is already past shows nothing.
3. **"The day concerned is today" (04-phases.md M3.3), with the switch on.**
   - The set-aside lines are used whenever a carry's source is today, or today is planned as missed and dropped.
   - This also covers the hour between the user's bedtime close and midnight: there the plan, not the user, closed the day, and the line still says "set aside". It is the decided wording for a day that is today.
   - With the switch off, M3.1 reads exactly as before.
4. **A carry from today wins over an older carry** in `signals.carried`, which the backend may list first. It is the user's latest action, and only one line shows (notice fatigue).
5. **A drop from "Set today aside"** is read from the stored body: today's `days[].kind` is `missed` and its id is in `carry.drops`. It stays until the next automatic reconcile replaces the body. After tonight's close it becomes M3.1's "Yesterday's session didn't happen. Nothing needs making up…".
6. **When the quiet buttons hide.**
   - Both hide when today is already the source of a move (the server would refuse `already_handled`), or already set aside (planned as missed, or holding an offer).
   - "Swap with another day" also hides on the test day and when today holds any moved step (R6).
   - A day holding a carried step can still be set aside, as the server allows.
   - The swap list also leaves out days that are the source of a move (the server would refuse them).
7. **After a successful set aside, today's session stays.** Start and Mark complete still work: the backend stores no status (M2.4), and nothing here hides today's work.
8. **"Swap the days" is `primary`, not gold.** "Start" stays the one gold action on the screen (Design.md §1).
9. **Where the failure lines go.**
   - "That didn't change. Please try again." sits beside the control: under the offer's buttons, or inside the open dialog. It uses `text-danger`, like Today's existing "That didn't save…".
   - "Your plan changed. Here's the latest." is a quiet status line under the main actions. The dialog closes, because its list may be stale.
10. **`reloadPlan`** is a second new context function. R7 needs "reconcile, then goal", and `loadGoal` toggles the loading state, which would unmount Today and lose the line.
11. **Focus after success.** Escape and "Keep today" return focus to the trigger (tested). After a successful action the trigger often disappears (today is now set aside), so the browser default applies.
12. **The swap list names the date's weekday** (`weekdayOf(date)`), as the notice lines do, not the stored `dayOfWeek`.
13. **No STOP on the endpoints.** The M2.4 code is unchanged since its report (`git diff 1a98c63..HEAD -- backend/src/routes/goal.ts backend/src/lib/reconcileCore.ts` is empty). Eligibility is decided from the stored steps' markers (`movedDays`) and the reconcile body. No backend change was needed.

## 8. Release checklist: turning carry-forward on (ND-15, 04-phases.md 2.4)

Do this only after M3.3 is merged to `main` and the Vercel deploy that carries it is live. Steps 1–10 are M3.1's; 11–19 are new.

**Turn on**
1. Confirm the M3.3 frontend is live. Open production with a plan v2 goal on an open practice day: no "Set today aside" or "Swap with another day" yet (the switch is off), and no "Yesterday's step wasn't completed" callout.
2. Render dashboard → service `achivii-api` → Environment. Set `MISSED_SESSIONS_CARRY_ENABLED` to exactly `true` (lowercase; anything else is off). Save, choosing the option that redeploys or restarts with the new value. It is `sync: false` in `render.yaml`, so a Blueprint sync never overwrites it.
3. Wait for the deploy to finish and `/api/health` to answer.

**Confirm automatic carry-forward (M3.1)**

Use a plan v2 test account with a pending practice day whose next practice day is open. Wait until the pending day closes (the user's bedtime + 2 h, capped at 04:00 local time).

4. In the network panel, the `POST /api/goal/reconcile` response has:
   - `carry.enabled: true`;
   - one entry in `carry.written` for that day;
   - `signals.notice: "carried"`.
5. The receiving day's `detailedSteps` (in `GET /api/goal/active`) holds the moved step with a `carriedFrom` marker. Its total minutes are not higher than before.
6. Today shows exactly one line: "Yesterday's session didn't happen. We moved its most important step into today, so today stays the same length." (or the "to {Weekday}" line).
7. The Dashboard agrees: "Yesterday's most important step is part of today's session." when the step moved into today.
8. Reload twice. The step moved once:
   - `carry.written` is empty and the move is in `carry.alreadyCarried`;
   - the receiving day has one carried step;
   - the line is still there.

**Confirm the three actions (M3.3)**

Use test accounts, each on an open practice day.

11. **Controls.** Today's view of today now shows "Set today aside" and "Swap with another day", quiet, under the main actions. A rest day, a completed day and another selected day show neither.
12. **Set today aside, carried** (an ordinary day whose next practice day is open):
    - "Set today aside" → the dialog → "Set it aside";
    - one `POST …/mark-missed` returns 200, then one `GET /api/goal/active`;
    - Today says "Today's session is set aside. We moved its most important step to {Weekday}, so that day stays the same length.";
    - that day holds the step with `carriedFrom` naming today, and its total minutes are not higher;
    - the quiet buttons are gone;
    - the Dashboard says "Today's session is set aside. No catching up needed.";
    - a reload keeps the line.
13. **Set today aside, dropped** (a high-load step, e.g. a run10k session, or the last practice day of the week):
    - Today says "Today's session is set aside. Nothing needs making up: the plan carries on as it is.";
    - no day changed.
14. **Set today aside on a key session:**
    - Today says "Today's key session is set aside. Do it {Weekday} instead?" with "Swap the days" and "Just move its main step";
    - "Swap the days" exchanges the two days (both carry `swappedFrom`), and the offer is gone.
    - Repeat on another account with "Just move its main step": the carried line appears, and the receiving day's total minutes are not higher.
15. **A past key session's offer** (a key session left pending until it closed, next practice day today):
    - Today says "Yesterday's key session didn't happen. Do it today instead?";
    - the Dashboard shows the same line without buttons;
    - check both answers as in 14.
16. **Swap with another day:**
    - the list holds only open practice days later this week, never the test day;
    - choosing one sends one `POST …/swap` with both days' `detailedSteps` as loaded;
    - Today shows the other day's session; the two days' dates and statuses are unchanged.
17. **Stale page.** Open the same account in two tabs. Swap in one, then try the same swap in the other: it says "Your plan changed. Here's the latest." and shows the swapped plan.
18. **Double click** "Swap the days" or "Set it aside": the network panel shows one request.
19. **Copy.** No screen says "missed", "behind", "failed" or "why", and no server message is ever shown.

**Turn off (kill switch)**

9. Render → `achivii-api` → Environment. Set `MISSED_SESSIONS_CARRY_ENABLED` to `false` or delete it, then save and redeploy as above. No code deploy is needed. From then on:
   - reconcile writes nothing (`carry.enabled: false`);
   - mark missed, swap and carry-now answer 409 `carry_disabled`;
   - the M3.3 controls and lines disappear on the next load.
10. Turning it off does not undo moves already stored.
    - Carries keep their `carriedFrom` markers, which store the steps they replaced (ND-13), so each can be reversed by a manual database edit (no tool exists yet).
    - Swaps keep their `swappedFrom` markers.
    - A carried notice keeps showing until its receiving day closes; with the switch off it reads as M3.1 does.
