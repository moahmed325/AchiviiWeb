# Missed Sessions — M3.2 Short-on-Time and Gentle Return

**Milestone:** P3 / M3.2
**Date:** 2026-10-07
**Status:** COMPLETE (frontend only; no backend change; `MISSED_SESSIONS_CARRY_ENABLED` untouched)
**Prompt:** docs/features/missed-sessions/05-prompts.md, M3.2 (commit `6da353d`)

## 1. Summary

- **Gentle-return day** (the first open practice day after a gap of 3+):
  - Today says "Welcome back. Today's a short one to ease in."
  - The gold action becomes "Start the 10-minute version", which opens Focus mode on the 10-minute version.
  - "Start the full session" is one tap away.
- **Two or more missed days this week, today still open** (`shortOnTime`):
  - **Start** stays the gold action.
  - "Start the 10-minute version" is added as a secondary button.
  - "The 10-minute version still counts toward this week." sits under the buttons.
- **Dashboard:** shows the same welcome line on a gentle-return day, read through the same `missNotice` (ND-19).
- **Honesty:** both behaviours need a 10-minute version on today's open practice day. Without one, nothing changes and nothing says "short".
- **Focus mode** takes `startWith: 'full' | 'minimum'` (default `'full'`), so every existing caller is unchanged.

## 7. Discrepancies, decisions and open questions

1. **Full-session minutes next to "a short one" (open question).**
   - On a gentle-return day, Today's step card still shows the full session's duration ("45 min"), and the Dashboard card shows "45 min · 2 steps", next to "Today's a short one to ease in."
   - The line is true: the default action is the 10-minute version, and the Dashboard's only action opens Today, where that is the default.
   - But the duration line describes the full session, which reads as mixed.
   - R2 and R4 do not cover it, so it was left as is. Options for a follow-up: show the 10-minute version's minutes on that day, or label the duration as the full session's.
2. **`Design.md` section 6** says the 10-minute version "is not the default path and not a second Start". M3.2 deliberately changes that on gentle-return and short-on-time days (Feature Definition UX-2, UX-4, AC-10; this prompt). `Design.md` was not edited (no copy or doc change was asked for); it should be updated with the M3.2 behaviour.
3. **Focus mode in the minimum version keeps the full timer and header minutes,** exactly as after the runner's switch today (R1 "exactly as if the user had used the runner's switch"). So a session started on the 10-minute version still shows the task's full minutes in the header and timer. This is existing behaviour, unchanged, and worth revisiting with item 1.
4. **The calm start screen is kept.** With `startWith: 'minimum'`, Focus mode still opens on its "Start focused session" screen (showing the minimum's instructions), so the timer only starts on the user's tap, as everywhere else. After that tap the runner is on the minimum version.
5. **No way back from the minimum version inside Focus mode.** The runner has none today, and R1 forbids adding one. On a gentle-return day the full session is the separate button on Today.
6. **Short-on-time line placement.** It sits under the whole button group (Start, Start the 10-minute version, Mark complete), as "directly under the buttons" in R3. On mobile it therefore appears under "Mark complete".
7. **Button sizes.** The gentle-return gold button is `lg` (56 px), like Start. Both secondary buttons are `md` (48 px). All are above 44 px.

No STOP condition applied:
- `signals` has every field needed.
- The 10-minute default needed no change to the runner on other days (`startWith` defaults to `'full'`).
- Each string is shown only where it is true, because both screens use the same helper and require a 10-minute version on an open practice day.
- No backend change was needed.
