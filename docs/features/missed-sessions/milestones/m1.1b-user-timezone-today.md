# Missed Sessions — M1.1b User-Timezone "Today"

**Milestone:** P1 / M1.1b
**Date:** 2026-10-07
**Status:** COMPLETE
**Decision implemented:** ND-1 — `User.timezone` is the single clock for "today"; `DailyTask.date` is the user's local calendar date.

## 1. Summary

"Today" now means the user's local calendar date everywhere it is computed. New goals start on the user's local day and every task date and weekday is derived by calendar arithmetic, so nothing depends on the server's timezone. Existing rows are untouched. No schema change, no new status value, no UI or copy change.

The work was done in two sessions: the backend and most of the frontend on 2026-10-04, and the remaining frontend callers, the frontend tests and this report on 2026-10-06/07.

## 4. How existing goals behave (R4)

Existing task dates were written as UTC dates and are not changed. They are now compared with the user's local date. For a user whose stored timezone is `UTC`, nothing changes. For anyone else, "today" can differ from before by at most one day, and only in the hours between local midnight and UTC midnight (for Addis Ababa, 00:00–03:00 local, the previous day's task now shows as yesterday instead of today). Old `targetDate` values are instants, so `dayNumber` may differ by at most one day near midnight for those goals. Nothing is hidden or duplicated: every task keeps its date, and review-due still fires once all dates are before the local today.
