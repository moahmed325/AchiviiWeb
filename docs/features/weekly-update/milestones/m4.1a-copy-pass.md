### Decisions I made
1. **"Held" for WU-61 (3)** means the week next week shows ends at exactly this week's target (any hold: the model's, a fallback's, or a restart at this level). Other option: only when a hold reason is in force. Why: the line says what the plan holds, so the plan is the test; it can't be untrue.
2. **The prompt line is on every prompt**, not only for a lower-is-better target. Other option: only when `direction` is `lower_is_better`. Why: the prompt asked for the pinned prompt to change, and a later week can differ from this one; one fixed line is simpler to pin.
3. **The two questions in the copy table** ("Did you do last week's test?", "Does {N} minutes a day still work?") pass the frontend "?" check by exact pattern. Other option: refuse them, which would change approved copy (a stop). Why: they are the table's own lines; the rule "never ask why" is about the update's sentence.
4. **Kind words:** only singular count nouns become plural, "Project piece" becomes "your project piece", "Catch-all" becomes "other work", "Played game with its review" becomes "played games and their reviews"; "or" names that read well stay. Other option: a word for every name. Why: smallest list that reads well.
5. **The review's two "already closed" lines** moved into `frontend/src/lib/weekClose.ts` (`WEEK_CLOSED_LINES`) so the copy test can read them. Other option: export them from `WeeklyReviewModal.tsx`, which `react-refresh/only-export-components` refuses (an error). Same words.
6. **Frontend copy test renders the cards** with `useAuth`, `useGoal` and the api mocked, instead of reading source text. Why: it checks what a person sees, including lines built from data.
