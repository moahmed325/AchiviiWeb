# EV-3 — P1 / M1.3 Premium Visual Foundation

**Date:** 2026-09-30
**Status:** COMPLETE
**Runtime changes:** None

## Verified foundation
The repository already contains a substantial shared visual system in `frontend/src/index.css` and reusable primitives in `frontend/src/components/ui/`. M1.3 therefore formalizes the existing foundation rather than introducing a new UI library or redesigning pages.

## Visual rules
1. **Typography:** Use the existing Geist/Inter UI stack and semantic display, H1-H3, body, small and micro roles. Headings communicate hierarchy through size, weight, line-height and tracking before decoration.
2. **Spacing:** Use the existing gutter/section rhythm and Tailwind spacing consistently. Group related information; create clear breathing room between priority levels.
3. **Content width:** Keep reading/action surfaces constrained to the existing page shells. Avoid unnecessarily wide text blocks and avoid shrinking primary content to make secondary content fit.
4. **Alignment:** Establish stable left edges and shared grids within a page. Primary content should align predictably with page title/context and primary action.
5. **Surfaces:** Prefer the existing background/surface/elevated-surface roles. Use borders, radius and elevation to distinguish meaningful groups, not every piece of content.
6. **Color:** Use semantic roles (`text`, `text-secondary`, `muted`, `accent`, `achievement`, `caution`, `danger`, borders). Do not introduce arbitrary page-specific colors without evidence.
7. **Status:** Never rely on color alone. Pair status color with text, icon, shape or semantic label.
8. **Controls:** Reuse shared `Button`, `TextLink`, `Tabs`, `Dialog`, `Field`, `Badge`, `Surface` and state primitives where appropriate. Do not create near-duplicate controls.
9. **Focus:** Preserve the shared visible focus treatment and ensure keyboard users can identify the active control.
10. **Disclosure:** Use existing interaction primitives where suitable. Disclosure labels must communicate what becomes available; state must be perceivable and keyboard-operable.
11. **Responsive:** Preserve semantic priority across desktop/mobile while allowing composition to change. Do not compress a dense desktop arrangement into an unreadable mobile column.
12. **Motion:** Motion is feedback/orientation, not decoration. Existing easing/duration/animation tokens may be reused. Reduced-motion rules must leave state meaning intact.

## Premium quality rules
Premium means calm, precise and intentional: strong type, composition, spacing, restrained color, coherent surfaces, polished controls and meaningful feedback. Do not use gradients, glass effects, decorative badges, shadows or animation merely to signal “premium”.

## Current implementation evidence
- `index.css` contains role-based color, typography, spacing, radius, shadow, easing, animation and reduced-motion tokens.
- Shared UI primitives already consume these roles in key areas.
- A repository scan found 97 references to core visual tokens across the inspected TypeScript/TSX source, confirming active adoption but also leaving room for page-level consistency work later.
- Existing Journey CSS includes disclosure animation and explicit reduced-motion handling.

## Reusable pattern decisions
- Page shell establishes width/gutter/rhythm.
- Page header establishes purpose/context before secondary navigation/detail.
- Primary action uses the shared control system; secondary actions remain visually subordinate.
- Surface is reserved for meaningful grouping, not used as a default container for every subsection.
- Detail disclosure must have an explicit accessible label and visible state.
- Status presentation always has a semantic/textual cue.
