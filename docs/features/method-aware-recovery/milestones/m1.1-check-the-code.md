### Requirements
Answer each with file paths and function names. Mark anything you could not confirm as a guess.

1. **Touch map.** Every place, backend and frontend, that writes, reads, moves, swaps, counts or describes a step or a day's steps, and which RULE (9 to 18) or AC each one will need. Include tests and e2e fixtures that pin current behavior.
2. **Where the profile lives.** Compare storing it inside `Goal.roadmap` (JSON, no migration) with a new column, including what `GET /active` sends to the browser and what the frontend would need. Recommend one.
3. **The pathways against the templates.** For each of the 10 pathways: which template it maps to, and whether its method, prose and the kinds of steps its weeks really contain fit that template's kinds. Use recorded fixtures (`frontend/e2e/fixtures/`) or test data for real weeks. List every mismatch.
4. **The kind list in the week call.** How a per-goal list of kinds can be a fixed menu in Gemini's schema and be checked for Groq; where the check and retry go; what happens to the existing `highLoad` field and the goal-level high-load rule (RULE-7).
5. **Order and rest gaps in the carry planner.** How `planCarries` and `fitCarriedStep` would apply RULE-9 to RULE-14; how "the next step of the same kind" and its order are found; how the swap check would apply RULE-14. Say what can stay pure and what touches the guarded writes.
6. **Continue.** Where the "Pick up where {Weekday} stopped." line would be stored so Today and Focus show it, without making the day longer, and how it stays idempotent with the guarded writes.
7. **Counts and screens.** Where `weekCounts` results reach the browser, and every screen that shows sessions done, skipped or dropped (RULE-17).
8. **Old steps and old goals.** How code can tell a step without a kind (RULE-18), and the right moment to give an existing goal its profile (RULE-1).
9. **The switch.** How `MISSED_SESSIONS_CARRY_ENABLED` is read today, and how `METHOD_RECOVERY_ENABLED` (03-phases section 3) should work alongside it.
10. **Clarify's domain.** What values `domain` really takes, and whether it is good enough to choose the fallback template (RULE-4).
11. **Docs that are wrong.** Anything in the brief, feature definition, phases or templates that the code contradicts, or that would make a milestone too big for one chat. Propose how to split it.
