# M3.2 — Swap, set today aside and move now follow the rules

## Prompt

### Context
The carry planner follows the kinds (M3.1a to M3.1d), but the person's own actions do not yet. Swap checks only missed sessions' rules, a held key session is held whatever its kind, and "move now" can answer 200 with nothing moved. This milestone makes the three actions follow RULE-16 on the server and has the server send the allowed choices. Everything new is behind `METHOD_RECOVERY_ENABLED` (off in production). Verify these facts; do not trust this prompt.

- The routes: `backend/src/routes/goal.ts`, `POST /tasks/:taskId/mark-missed`, `/carry-now` and `/swap`, with `ActionReason`, `ACTION_ERRORS`, `refuse`, `actionGoal` and `hasCarriedStep` (it knows only `carriedFrom`). Each answers with `runReconcile`'s body.
- `backend/src/lib/reconcileCore.ts`: `evaluate` (overrides `asMissed`, `asNotKey`), `runReconcile`, `methodRecoveryEnabled()`. The method fields of the body appear only when the switch is on (MR-28 (6)).
- `backend/src/lib/recovery/carry.ts`, `planRecovery`: the hold comes unchanged from missed sessions (`legacy.held`, `heldIds`; outcome `held`). `isHard`, `restGapHolds` and `isProtected` are closures inside `planRecovery`. `actionOf` is in `recovery/profile.ts`; `inOrderMoveKinds` and `inOrderQueue` are in `recovery/inOrder.ts`; `markerOf` and `swapMarkerOf` are in `lib/carryForward.ts`. Markers: `carriedFrom`, `swappedFrom`, `continueFrom`, `shiftedFrom`, plus `toNextWeek` records.
- The frontend works out its own choices (`todayActions` in `frontend/src/lib/today.ts`). A 409 other than `changed` becomes a quiet failure (`usePlanAction.ts`), so new reasons cannot break the screen. The frontend is M3.3's: do not change it here.

### Goal
With the switch on, a swap is allowed only when it keeps fixed steps, order and rest gaps (RULE-12 to RULE-14); a key session is held for its swap offer only when its main step moves; "move now" is offered and done only when it really moves the step. The reconcile body lists the allowed choices, and the routes refuse anything not allowed, from the same checks. With the switch off, every route and the reconcile body are exactly as today.

### Requirements
1. **Switch off means exactly today.** Every change below acts only when `METHOD_RECOVERY_ENABLED` is exactly `true`, read per request. The one exception is requirement 6. With it off, the existing route and reconcile tests pass unchanged, and a test compares the reconcile body exactly with today's.
2. **One swap check (RULE-12, RULE-13, RULE-14).** A pure function decides whether two days of the same week may swap. It is used for the choices (requirement 5), the hold (requirement 3) and the swap route (requirement 6). With a valid profile, a swap is allowed only when:
   - **Fixed (RULE-12, MR-17):** neither day holds a step whose action is fixed. This covers a Weekly test or Fixed-time session step, and any kind the profile makes fixed. The test day stays refused as today.
   - **Order (RULE-13, RULE-20):** after the swap, each in-order kind's steps that are not done still come in written order by date. For example, Lesson 3 today and Lesson 4 on Thursday: no swap between them, and no swap that moves Lesson 3 past Lesson 4.
   - **Rest gap (RULE-14, MR-29):** each hard step that changes day is checked at its new day against every other hard step on done or open days, in calendar days and including last week, as `restGapHolds` counts today. A swap is refused only for a breach it creates. Closeness the writer already put in the week does not block a swap that does not touch it.
   - Steps without a kind (RULE-18) are never fixed or in-order, and are hard only when `highLoad` (RULE-7). Without a valid profile, only today's checks apply.
   - A swap trades the two days' lengths. That is the person's choice, so there is no "no day longer" check for a swap. Lift `isHard`, `restGapHolds` or whatever else the check needs out of `planRecovery` so both share one copy. That refactor is in scope; `planRecovery`'s behavior must not change.
3. **The hold (RULE-16, MR-28 (3)).** A key session is held for its swap offer only when its priority-1 step's action is move (after RULE-7's overrides) **and** swapping it with its receiving day passes requirement 2. Otherwise its day is an ordinary missed day under the new rules: it is moved, continued, let go, fixed or no room by its kinds. That applies both to a past key session and to today's key session set aside. Days that keep missed sessions' rules (RULE-18) keep today's hold.
4. **Move now (RULE-16, MR-21 (2); carried-over item 2).** For a held key session, "move now" is offered only when planning that day with `asNotKey` really carries its step somewhere. The choices name that day. When it would not, the carry-now route refuses with a new 409 reason (for example `would_not_move`) and writes nothing. It never answers 200 with nothing carried. A move-now never breaks order or rest gap, and no day gets longer (it is a RULE-9 move).
5. **The server sends the choices (RULE-16).** With the switch on, the reconcile body gets `carry.choices`:
   - **Today:** its task id, whether "set today aside" is offered (always, unless today is already handled or set aside, as today), and the days today may swap with (open practice days later this week that pass requirement 2).
   - **Each held key session:** its id, its receiving day, and the move-now day (or null).
   Choose the exact field names and list them under "Decisions I made". M3.3 will read this instead of `todayActions`. The actions' answers carry it too, since they return the reconcile body.
6. **The swap route refuses what is not allowed (carried-over items 1 and 3).**
   - **Any switch state:** refuse a day holding a `continueFrom` or `shiftedFrom` step, as `holds_carry` does for `carriedFrom`. These markers exist only if the switch was on at some point, so this does not change today's behavior on stored data written with the switch off. Use a new reason or widen `holds_carry`, and say which.
   - **Switch on:** refuse any pair, open swap or offer answer, that fails requirement 2, with a reason naming the rule (for example `fixed_step`, `out_of_order`, `rest_gap`). The route and the choices must never disagree: the route calls the same function.
   - The new `ACTION_ERRORS` texts follow the existing tone. No screen shows them.
7. **Set today aside.** Check that `mark-missed` on today follows the new rules through `runReconcile` (a let-go day writes nothing, a move day moves by RULE-9, a held key session follows requirement 3). Add the tests that are missing.
8. **Tests.**
   - Switch off: route answers and reconcile body exactly as today.
   - Swap: refused onto and off a day with a fixed step; refused when it breaks order, both ways; refused when it creates a rest-gap breach; allowed when the writer's own closeness is untouched; refused on `continueFrom` and `shiftedFrom` days with the switch both on and off.
   - Hold: a key session whose main step lets go or continues is not held and follows its kind; one whose swap would break the rest gap is not held and moves by RULE-9.
   - Move now: offered with its day when it moves; refused with the new reason, and nothing written, when it would not.
   - `carry.choices` for today and for a held offer, and the route agreeing with it.
   - Set today aside on a let-go, move and key day.
   - **Generated tests (AC-6, AC-8):** over many random tagged weeks and profiles, every swap in the choices keeps fixed steps, order and rest gap; every pair the choices leave out is refused by the route; every move-now keeps order and rest gap and makes no day longer.
