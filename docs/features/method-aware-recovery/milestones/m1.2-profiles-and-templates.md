### Requirements
1. **The profile type.** Holds: the template it came from; its kinds (each with a stable id, a name, a one-line description the week writer can use, an action of move, continue, let go or fixed, a hard flag and an in-order flag); which kind is the catch-all; the rest gap in days (0 to 2); and the return rule in the format of the templates file (one or two break lengths, each with a restart of last level, back 1 week or back 2 weeks, plus a "first week back" note). Put the feature's code in its own folder (suggested: `backend/src/lib/recovery/`). (RULE-1, MR-9)
2. **The checks (RULE-4).** One pure function that returns the list of reasons a profile fails, empty when it passes: one action per kind; 2 to 8 kinds plus the catch-all; no hard kind with continue; rest gap 0 to 2; a kind marked high-load is hard; for a goal whose week-12 target is a deliverable, the catch-all is continue (take that fact as an input); the return rule in the checked format; unique kind ids. (RULE-4, MR-21)
3. **The two added kinds.** A function that adds **Weekly test** and **Fixed-time session**, both fixed, to any profile, and that the checks expect. (RULE-5)
4. **The 13 templates,** exactly as in the templates file, each passing the checks. Kind descriptions are yours to write: one plain sentence each, saying what the step looks like. (MR-13, MR-20)
5. **The 10 pathway profiles,** one per preset id, each built from its template and adjusted only where the pathway's method needs it (read each preset's method text). List every adjustment you make, with the reason, in the report. Each passes the checks. Keep them in the recovery folder keyed by preset id; do not edit the preset files. (RULE-2)
6. **The keyword table.** A pure function that picks a template from the clarify domain (optional), the goal text and the method name, with no model call, and returns General practice when nothing matches. It must pick each pathway's own template for that pathway's goal text, and General practice for "Bake sourdough bread at home". (MR-13, MR-14)
7. **The checked reader.** Reads `recovery` from a stored roadmap value and returns the profile only when it passes the checks; otherwise none. Never throws. (MR-9)
8. **`actionOf`.** For a step and a profile (either may be missing), returns the action and whether the step is hard, or none. None when there is no profile, no `kind`, or a kind not in the profile (RULE-18 follows from none, MR-5). The test step is always fixed (by kind Weekly test, and by the same test-step check `carryForward.ts` uses today). A `highLoad` step is always hard, and a `highLoad` step whose action would be continue is treated as move. (RULE-7, MR-11)
9. **Tests.** Every check in 2, each passing and failing case; all 13 templates and 10 pathway profiles pass; the keyword table for every pathway, for sourdough, and for a domain-only match; the reader on missing, malformed and invalid values; `actionOf` on every case in 8.
