## 1. Objective
Create a repository-grounded map of the three core experiences before page redesign work begins.

## 2. Route / page map
- `/` → `Home.tsx`; authenticated active-goal users render `Today`.
- `/roadmap` → `RoadmapPage.tsx`; renders Journey header plus desktop/mobile journey views and strategic roadmap.
- `/progress` → `ProgressPage.tsx`; renders progress header plus five evidence/history layers.
- Completed active goals on `/` render `AchievementPage` instead of Today.
- App navigation exposes Today, Roadmap, Progress, Pathways, Coach and Account according to current goal/state rules.

1. `JourneyHeader`

## 7. Design inventory
`frontend/src/index.css` contains an established role-based token system for:
- background/surfaces/text/accent/status colors
- typography scale and font roles
- spacing/gutter/section rhythm
- radii and shadows
- motion/easing/animation tokens

The foundation therefore exists, but M1.3 must verify actual adoption and consistency rather than assume tokens are universally used.

- Focus-ring classes and reduced-motion CSS are present.
- Roadmap explicitly prevents horizontal overflow at its page shell.
- Full responsive/accessibility behavior still requires implementation-phase validation.
