## 1. Summary

`DailyTask` now has `usedMinimumVersion Boolean @default(false)`, added by one new migration that has **not** been applied anywhere. `PATCH /api/goal/tasks/:taskId` sets the flag whenever a task's completion changes: `true` only for a Focus mode "Complete minimum" on a task that has a minimum version, `false` for every other completion and for un-completing. Updates that don't change status leave it alone. Nothing reads the flag yet; M2.3 will. Nothing on screen changed. No database was contacted.

> **The migration is not applied.** `render.yaml` runs `npx prisma migrate deploy` on every backend deploy, so this migration will be applied to the deployed database on the next Render deploy after it reaches `main`. Existing rows get `false` from the column default at that point. No backfill.

## 6. Discrepancies and decisions

1. **Migration drift (pre-existing, not changed).** The STOP IF list includes drift between the migration history and `schema.prisma`. With no shadow database allowed, the check was done offline: every migration's SQL was replayed into a table/column map and compared with `prisma migrate diff --from-empty --to-schema-datamodel`. Result: `20260928171500_add_user_billing_fields` adds six `users` columns (`plan`, `stripeCustomerId`, `stripeSubscriptionId`, `subscriptionStatus`, `currentPeriodEnd`, `cancelAtPeriodEnd`) and two unique indexes that are not in `schema.prisma`. This is the drift already recorded in `docs/features/infra-migration/reference/migration-brief.md`. Two hand-written `research_cache` indexes (HNSW, GIN) also differ, as expected, because the schema cannot express them. Work stopped and was reported; the go-ahead was to proceed as recommended (leave the drift, record it here). The drift does not affect this migration: it touches only `daily_tasks`, it was diffed from the schema at HEAD rather than from the history, and after it the `daily_tasks` table matches exactly. Carry-over: resolve the drift separately before anyone runs `prisma migrate dev`, which would try to drop those columns.
2. **Roadmap says "apply".** `04-phases.md` 7.7 says M2.0 should "Generate and apply the Prisma migration". The prompt and Mo's instructions say file only, so it was not applied. Suggest updating 7.7.
3. **Status values other than `completed`/`pending`.** R3 is silent; the route accepts any string (the frontend type allows `skipped`). Decision: any `status` other than `completed` stores `false`, since there is then no completion to describe. Covered by the same code path as `pending`.
4. **Validation order.** The 400 for a non-boolean flag comes after the 401 check and before the task lookup, so it is returned without a read or write.
