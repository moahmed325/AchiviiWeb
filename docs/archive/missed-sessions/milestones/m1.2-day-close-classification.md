# Missed Sessions — M1.2 Day-Close and Classification

**Milestone:** P1 / M1.2 (pure functions only)
**Date:** 2026-10-07
**Status:** COMPLETE
**Prompt:** docs/archive/missed-sessions/05-prompts.md, M1.2

## 1. Summary

The backend can now decide, for any instant, when each day of a plan closes, whether each task is done, missed, rest or planned, and whether a gap (3+ missed practice days in a row) is open. Everything is a pure function: no database, no route, no `new Date()`, no schema change, no new `status` value. Results do not depend on the server's timezone. M1.3 will call these from `POST /api/goal/reconcile`.

## 4. Interpretations and limits

- **Partial-day credit (R5).** Completion is stored per day (`status`, `completedAt`), never per step, so "at least one step done" and "the P1 step was done but later steps were not" (Feature Definition sections 6 and 10) cannot be computed. A day is done only when it is marked completed. The 10-minute version counts as done because it is stored the same way. Consequence: someone who does part of a session and closes the app without completing it is classified as missed. Going further needs per-step completion stored on `DailyTask` (a schema or JSON change plus a frontend write), which is outside P1. Recorded as ND-8 in `04-phases.md`.
- **Close is on the local clock.** "Bedtime + 2 hours" is added on the wall clock, then turned into an instant. On a DST night the elapsed time can be 1 or 3 hours; the close is still the clock time the user would expect (for example 01:00).
- **Bedtime reading.** 18:00-23:59 is that evening; 00:00-17:59 is after midnight, so it reaches the 04:00 cap unless it is before 02:00. A day therefore closes between 20:00 that evening and 04:00 the next morning.
- **Existing goals.** Their task dates were written as UTC dates before M1.1b. Classification reads them as local dates (ND-1), so a close can differ by at most one day from what the old date meant, only for goals created before M1.1b.
