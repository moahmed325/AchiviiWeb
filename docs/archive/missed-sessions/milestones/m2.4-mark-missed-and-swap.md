## 1. Summary

Three endpoints let a user change this week's plan by hand:

- **Mark today missed** (`POST /tasks/:id/mark-missed`).
- **Swap two days** (`POST /tasks/:id/swap`), either an open swap or the answer to a key session's swap offer.
- **Carry now** (`POST /tasks/:id/carry-now`): "just move the main step" for a held key session.

All three share one reconcile core with `POST /reconcile`, apply the M2.2 rules unchanged, and answer with the reconcile body. They write only when `MISSED_SESSIONS_CARRY_ENABLED` is exactly `true`; otherwise they answer 409 `carry_disabled` and write nothing.

ND-18 is in place:

- A manual carry shows in `signals.carried` at once.
- Steps that land on a day through an answered swap offer carry `swappedFrom`, so neither day is carried, held or dropped afterwards.

`POST /reconcile` behaves exactly as before. No schema change, no frontend change, no copy beyond error messages. With this, P2 is complete.

## 3. Endpoints: request and response

All three are `POST`, need `Authorization: Bearer`, and answer 200 with **the reconcile body**: `{ applies, goalId, asOf, timezone, days, gap, carry, signals }`, as `POST /reconcile` returns it.

| Endpoint | Body | What it does |
|---|---|---|
| `/api/goal/tasks/:taskId/mark-missed` | none | Today's open practice day is planned as missed (`asMissed`). The result is a carry (one guarded write), a hold for a swap offer (key session), or a drop. Only a carry writes. In the response, that day's `days[].kind` is `missed` and `gap` is recomputed with it. |
| `/api/goal/tasks/:taskId/swap` | `{ "withTaskId": "…", "expected": { "<taskId>": "<detailedSteps>", "<withTaskId>": "<detailedSteps>" } }` | Exchanges the content fields of the two days in one transaction (compare-and-set on `expected` and `status` for each). Answering a swap offer also writes `swappedFrom` on every step that lands. The body is a fresh reconcile after the write. |
| `/api/goal/tasks/:taskId/carry-now` | none | The held key session's priority-1 step is carried as M2.2 carries an ordinary day (`asNotKey`): fit rule, high-load, guarded write. The response's `days` keep the real `isKeySession`. |

**Errors.** `{ error, reason }`:

| Status | When |
|---|---|
| 401 | No signed-in user. |
| 400 | Swap body malformed: `withTaskId` missing, empty or equal to `taskId`; `expected` not an object holding a string for each id. |
| 404 | `{ error: 'Task not found.' }`: no active goal, or the task is not in the user's active goal. |
| 409 `not_plan_v2` | The active goal is plan v1 (every action, switch on or off). |
| 409 `carry_disabled` | The switch is not exactly `'true'`. |
| 409 `not_today`, `rest_day`, `completed`, `already_handled` | Mark missed guards. `already_handled` also answers carry-now and swap for a day that is the source of a carry or swap marker, or that holds a swapped step. |
| 409 `not_held` | Carry-now on a day that is not held. |
| 409 `not_same_week`, `rest_day`, `test_day`, `completed`, `not_open`, `holds_carry` | Open-swap guards (`not_open`: not classified `planned`, or dated before today). |
| 409 `changed` | `expected` differs from the stored steps, or a write in the transaction matched no row (rolled back). |

The order of checks is 401, 400 (swap), 404, `not_plan_v2`, `carry_disabled`, then the action's own guards.

## 5. Discrepancies and decisions

1. **Carry-now after "mark today missed" (a gap between ND-14 and R4).** Mark missed stores nothing for a key session (ND-14), so a plain reconcile does not see today's key session as held until tonight's close, and the swap offer from mark missed lives only in that response. To keep "mark missed → swap offer → just move the main step" working, carry-now plans the user's own open task dated today as missed before checking that it is held, exactly as mark missed would. Anywhere else, carry-now needs a hold that a plain reconcile sees. The swap-offer shape still needs a hold that a plain reconcile sees (a past missed key session). To swap today's key session with another open day, the open swap covers it. P3 should use the `swapOffer` from the mark-missed response directly.
2. **"Repeat is a no-op" vs `already_handled`.** A repeat of mark missed or carry-now after a carry answers 409 `already_handled` and writes nothing. It is a no-op in effect, and the guard is the one the prompt lists. A swap repeat answers 409 `changed`.
3. **Shape of a swap.** A swap is treated as an answer to an offer when the plan holds `taskId` with `withTaskId` as its receiving day; otherwise it is an open swap with the open-swap guards. An open swap is also refused (`already_handled`) when either day holds a `swappedFrom` step, so an answered offer's markers are never moved onto a third day.
4. **404 scope.** A task that belongs to the user but not to the active goal (an archived goal) answers 404, because every action is only for the active plan v2 goal. `PATCH /tasks` still allows such tasks; it is unchanged.
5. **Field ownership.** The content and date-and-user lists from the prompt are used as given. `created_at` is a row field and is not moved. `implementationIntention` moves with the content; it embeds a time ("At 19:30: …") that normally equals both days' `slotTime`, because the week plan writes one slot for the whole week. If a user changed one day's slot through `PATCH /tasks`, the moved intention text would show the other day's time. This doesn't affect any decision, so it is recorded here rather than stopped on.
6. **`minimumVersion: null`** is written as `Prisma.DbNull`, so a day without a 10-minute version stays without one after a swap.
7. **A manual drop is not shown as a notice until the day closes.** The `dropped` signal follows M2.3 (the most recent *closed* practice day), and ND-18 only changes `carried`. The drop is still in `carry.drops` of the mark-missed response.
8. **Error messages** are neutral and never say "missed"; P3 writes the words users see.

## 8. Carry-overs for P3 (M3.3)

- **When to call what.**
  - "Mark today missed" on today's open practice day → `POST /tasks/:id/mark-missed`. Render the returned `signals.notice`. If it is `swap_offer`, keep that response's `swapOffer`: a reload won't show it again until tonight's close.
  - A swap offer (`signals.swapOffer`) has two answers:
    - **Swap:** `POST /tasks/:missedTaskId/swap` with `withTaskId: swapOffer.receivingTaskId` and `expected` holding both days' `detailedSteps` strings exactly as loaded.
    - **Just move the main step:** `POST /tasks/:missedTaskId/carry-now`.
  - "Swap today with another day" (open swap) → `POST /tasks/:todayId/swap` with the other day's id and both `expected` strings.
- **After any 200**, replace the client's reconcile state with the body. After a 409 `changed`, reload the goal (`GET /active`) and reconcile.
- **While the switch is off,** every action answers 409 `carry_disabled`. The UI should not offer these actions until the switch is on (ND-15, 2.4).
- **Types.** The frontend needs `carry`, `signals` and the three calls in `lib/api.ts`. `detailedSteps` is already the stored string, so `expected` can be sent as loaded.
