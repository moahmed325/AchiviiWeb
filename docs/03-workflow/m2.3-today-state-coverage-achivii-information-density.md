## Objective

Apply the approved Today hierarchy to every meaningful Today-related state without changing lifecycle, generation, API, or data behavior.

## State coverage conclusion

The current repository already contains intentional state-specific composition from the existing Today implementation and prior milestones. M2.3 therefore required verification and evidence, not a second redesign.

- **Loading:** Home/TodaySkeleton communicates that the day is loading before normal content.
- **No active goal:** Home presents a focused start state with pathway selection and a clear create/choose action.
- **Practice:** Today leads with goal context → current session → Start.
- **Key session:** Key-session badge and pivotal-session callout elevate the special purpose while retaining Start.
- **Test day:** Test-day badge and benchmark purpose/instructions appear before supporting detail; no invented result input is introduced.
- **Rest day:** Rest is explicitly labeled, Start is suppressed, and recovery logging becomes the primary actionable path.
- **Minimum version:** The 10-minute version remains available as an intentional secondary disclosure rather than competing with the normal session.
- **Done:** Completion state receives explicit confirmation and a next-step/week-review bridge.
- **Yesterday pending / recovery:** Recovery guidance is shown before normal detail and uses non-punitive forward guidance.
- **Review due / failed:** Review-due state is promoted above the normal session when review is the immediate need; failed review retains the existing retry/error path.
- **Closing stretch:** ClosingStretchView replaces normal practice composition when the final evaluation/arrival state is active.
- **Completed goal:** Home routes completed goals to AchievementPage rather than pretending the normal Today session is still active.
- **API offline:** Today displays a persistent status explanation while preserving read access and honest save limitations.
- **Goal-load error:** Home presents a dedicated error state with explanation and retry rather than falling through to the pathway library.

## Hierarchy rules verified

1. Every exercised state has one identifiable primary message.
2. Actionable states expose an obvious next step.
3. State-specific needs override the normal practice ordering when necessary.
4. Existing execution, review and recovery behavior remains intact.
5. Errors explain the problem and provide recovery.
6. Completion does not fabricate continued practice.
7. Secondary detail remains discoverable.
8. Mobile/keyboard/status semantics continue to use existing patterns.
